Olá, leitores! Bem-vindos à edição #21 da CyberSecNews. Esta semana foi marcada por ataques supply chain em larga escala atingindo ecossistemas críticos de desenvolvimento, um zero-day no cPanel sendo explorado silenciosamente desde fevereiro, e uma falha lógica no kernel Linux que persiste desde 2017. Também cobrimos campanhas da Coreia do Norte usando IA para inserir malware e novas ameaças que miram profissionais de DevOps e segurança. Vamos aos detalhes.

Crítico

Zero-Day no cPanel & WHM explorado desde fevereiro (CVE-2026-41940)

Uma vulnerabilidade crítica de autenticação bypass no cPanel, WHM e WP Squared, rastreada como CVE-2026-41940, está sendo explorada ativamente desde fevereiro de 2026. A falha permite que atacantes obtenham acesso administrativo a servidores vulneráveis sem autenticação. Um proof-of-concept (PoC) já está disponível publicamente, o que amplifica significativamente o risco de exploração em massa.

O cPanel é um dos painéis de controle de hosting mais utilizados no mundo, gerenciando milhões de servidores. A disponibilidade do PoC significa que atacantes menos sofisticados podem agora explorar a vulnerabilidade. Servidores de shared hosting são particularmente vulneráveis, pois um único servidor comprometido pode afetar centenas de sites.

A janela de exploração de dois meses antes da detecção pública é alarmante e sugere que a vulnerabilidade foi usada em ataques direcionados antes de se tornar conhecida. Organizações que utilizam cPanel devem aplicar patches imediatamente e verificar logs de acesso para indicadores de comprometimento desde fevereiro.

Ação: Atualizar cPanel/WHM imediatamente; verificar logs de acesso desde fevereiro; restringir acesso ao painel administrativo via IP.

PyTorch Lightning comprometido em ataque supply chain via PyPI

Em mais um ataque à cadeia de suprimentos de software, atacantes conseguiram comprometer o popular pacote Python Lightning, publicando duas versões maliciosas (v2.6.2 e v2.6.3) no PyPI em 30 de abril de 2026. O PyTorch Lightning, um framework com mais de 31.100 stars no GitHub, foi colocado em quarentena pelos administradores do PyPI. O ataque é uma extensão da campanha Mini Shai-Hulud que anteriormente atingiu pacotes npm do SAP.

O pacote malicioso inclui um diretório oculto _runtime contendo um downloader e um payload JavaScript ofuscado. A cadeia de execução é disparada automaticamente quando o pacote é importado, tornando o ataque extremamente eficaz contra desenvolvedores que atualizam dependências sem verificação manual.

O impacto é amplificado pelo fato de que PyTorch Lightning é amplamente usado em projetos de machine learning e IA. Desenvolvedores que atualizaram o pacote entre 26 e 28 de abril devem considerar seus ambientes comprometidos e rotacionar todas as credenciais e tokens acessíveis pelo ambiente de desenvolvimento.

Ação: Verificar se usou pytorch-lightning==2.6.2 ou 2.6.3; se sim, rotacionar credenciais e tokens; usar pip install --no-deps para instalações verificadas.

Pacotes npm oficiais do SAP comprometidos (Mini Shai-Hulud)

Pesquisadores de segurança soaram o alarme sobre uma nova campanha de ataque supply chain que comprometeu pacotes npm oficiais do SAP. A campanha, batizada de Mini Shai-Hulud, afetou pacotes como mbt@1.2.48, @cap-js/db-service@2.10.1, @cap-js/postgres@2.2.2 e @cap-js/sqlite@2.2.2. As versões comprometidas introduziram scripts de preinstall que baixam e executam um binário Bun de um repositório GitHub.

A técnica de usar scripts de preinstall é particularmente perigosa porque a execução acontece automaticamente durante npm install, sem interação do desenvolvedor. O Bun binary baixado segue redirecionamentos HTTP e executa imediatamente, estabelecendo persistência e exfiltrando credenciais e tokens de autenticação do ambiente de desenvolvimento.

O ecossistema SAP é amplamente utilizado em ambientes corporativos, o que torna este ataque especialmente preocupante para empresas que dependem de ferramentas SAP para suas operações. Desenvolvedores que trabalham com SAP CAP (Cloud Application Programming) devem verificar imediatamente suas dependências.

Ação: Verificar package-lock.json para versões afetadas; usar npm audit para detectar comprometimento; rotacionar credenciais SAP e tokens de desenvolvimento.

Linux "Copy Fail" — Falha lógica dá root em todas as distros desde 2017

Um exploit foi publicado para uma vulnerabilidade de escalação de privilégio local batizada de "Copy Fail" que afeta kernels Linux desde 2017. A falha, introduzida no template criptográfico authencesn do kernel, permite que um atacante local não-privilegado obtenha permissões root em todas as distribuições Linux.

A natureza da vulnerabilidade — uma falha lógica no código criptográfico — significa que ela persistiu por quase 9 anos sem detecção. O exploit publicado torna a exploração trivial para qualquer atacante com acesso local ao sistema. Servidores de shared hosting, containers com escape e ambientes multi-tenant são os mais vulneráveis.

O impacto é universal: todas as distribuições Linux com kernel compilado desde 2017 são afetadas. A mitigação imediata requer a atualização do kernel para uma versão corrigida, mas como a falha está no template criptográfico, patches específicos podem ser aplicados sem atualização completa do kernel.

Ação: Atualizar kernel Linux imediatamente; priorizar servidores de shared hosting e ambientes multi-tenant; monitorar tentativas de escalação de privilégio.

DPRK usa IA para inserir malware em pacotes npm (Campanha PromptMink)

Pesquisadores descobriram código malicioso em um pacote npm após ele ser adicionado como dependência por Claude Opus, o large language model da Anthropic. O pacote @validate-sdk/v2, listado no npm como SDK utilitário, é na verdade um infostealer que rouba secrets do ambiente comprometido. A campanha foi batizada de PromptMink pela ReversingLabs e ligada ao grupo norte-coreano Famous Chollima.

Este é um marco significativo: a primeira campanha documentada onde IA generativa foi usada para inserir malware em um ecossistema de pacotes. O pacote mostra sinais de ter sido "vibe-coded" usando IA generativa, sugerindo que atacantes estão explorando a confiança que modelos de IA têm em dependências de terceiros.

A campanha faz parte da operação Contagious Interview e do esquema de IT Workers fraudulentos da Coreia do Norte. O uso de IA para criar e distribuir malware representa uma evolução na sofisticação das táticas APT, onde a própria ferramenta de desenvolvimento se torna vetor de ataque.

Ação: Auditar dependências npm para @validate-sdk/v2; implementar verificação de integridade de pacotes antes de usar IA para sugerir dependências; usar lockfiles.

SonicWall urge patches imediatos para vulnerabilidades em firewalls

A SonicWall divulgou vulnerabilidades em seus firewalls que podem ser exploradas para bypass de controles de segurança, acesso a serviços restritos e crash dos dispositivos. A empresa recomenda aplicação imediata dos patches, pois as vulnerabilidades representam risco significativo para ambientes corporativos que dependem dos firewalls SonicWall para proteção perimetral.

Firewalls são o primeiro linha de defesa em redes corporativas, e vulnerabilidades nesses dispositivos podem comprometer toda a postura de segurança de uma organização. O bypass de controles de segurança permite que atacantes contornem regras de firewall, enquanto o crash do dispositivo pode criar janelas de exposição temporária.

A rapidez na aplicação de patches em dispositivos de segurança perimetral é crítica. Organizações que utilizam SonicWall devem priorizar esta atualização e verificar se há indicações de exploração nos logs de firewall.

Ação: Aplicar patches SonicWall imediatamente; verificar logs de firewall para anomalias; considerar regras temporárias de mitigação se o patch não puder ser aplicado imediatamente.

DEEP#DOOR — Backdoor Python stealth rouba credenciais de browser e cloud

Pesquisadores da Securonix divulgaram detalhes sobre um framework de backdoor Python chamado DEEP#DOOR, capaz de estabelecer acesso persistente e colher uma ampla gama de informações sensíveis de hosts comprometidos. A cadeia de intrusão começa com a execução de um script batch que desabilita controles de segurança do Windows e extrai um payload Python embutido.

O malware utiliza múltiplos mecanismos de persistência, incluindo scripts na pasta Startup, chaves Run do registro, tarefas agendadas e subscrições WMI opcionais. A capacidade de tunneling permite que o malware roube credenciais de navegadores e serviços de cloud sem detecção por soluções de segurança baseadas em rede.

A distribuição ocorre via phishing tradicional, mas a sofisticação técnica do framework é notável. A combinação de persistência multi-camada, evasão de controles de segurança e exfiltração de credenciais torna o DEEP#DOOR uma ameaça significativa para ambientes corporativos.

Ação: Monitorar scripts batch que desabilitam controles de segurança; verificar persistência em Startup, registro e tarefas agendadas; implementar detecção de tunneling.

EtherRAT via GitHub Facades mira administradores e profissionais de DevOps

Uma campanha sofisticada identificada pelo Atos Threat Research Center (TRC) em março de 2026 mira especificamente contas de alto privilégio de administradores de TI, engenheiros DevOps e analistas de segurança. A campanha utiliza SEO poisoning, uma arquitetura de distribuição dual-stage via GitHub e C2 baseado em blockchain para criar um mecanismo de entrega altamente resiliente.

O ataque começa com SEO poisoning em mecanismos de busca como Bing, Yahoo, DuckDuckGo e Yandex, garantindo que resultados maliciosos para termos técnicos de TI apareçam no topo. Os repositórios GitHub servem como fachada para distribuir o EtherRAT, um trojan de acesso remoto com capacidades completas de controle do sistema.

A infraestrutura baseada em blockchain para resolução de C2 é particularmente inovadora, tornando o takedown extremamente difícil pois não depende de domínios centralizados que podem ser apreendidos. Profissionais de segurança que buscam ferramentas administrativas devem verificar a autenticidade das fontes antes de baixar.

Ação: Baixar ferramentas apenas de fontes oficiais; verificar hashes e assinaturas; desconfiar de resultados de busca para ferramentas administrativas; implementar verificação de integridade.
